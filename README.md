# Accessibility Probe

Inspect a local UTF-8 HTML file for selected potential labeling problems: images missing an `alt` attribute, duplicate IDs, and some inputs, buttons and links without obvious labels or text. The result includes line numbers and a source fingerprint; document contents are treated as untrusted data. A separate keyboard walkthrough loads the local document in isolated headless Chrome or Chromium, presses Tab, and compares focused elements against a supplied list of CSS selectors. Page JavaScript and network requests are disabled, and the browser runs in a separate credential-scrubbed process.

The HTML checks use static heuristics, not a browser accessibility tree. The keyboard walkthrough covers only static local content with JavaScript disabled. Neither can reliably establish complete accessible names, visual focus, dynamic application behavior, screen-reader behavior, contrast or conformance. Some findings can be false positives or false negatives. Inspect the rendered page and perform real keyboard and assistive-technology testing before drawing conclusions. Six synthetic tests include a real headless browser focus journey and a blocked local network request. No production site, dynamic journey, or assistive-technology test has been completed. Playwright is declared in the manifest, and a compatible local Chrome or Chromium is required; browser binaries are not bundled. The headless process-management path has been tested on Linux only.
