# Verification

- Mixed-case protected-directory fixtures passed on Linux and native Windows; no real credentials were used. This is not a full platform or publication audit.

- Native Windows Python 3.14 identified a missing image alt attribute in a synthetic static HTML file. A later isolated Playwright 1.64.0 environment ran a real headless Edge walkthrough on two fictional buttons, confirmed JavaScript and a local network request were blocked, and verified the worker did not inherit a synthetic credential. A mocked timeout test checked the cleanup request; a separate real timeout fixture confirmed that its owned child process was no longer active. This does not cover every failure case or Windows ACLs.
- Earlier Linux fixtures covered static labeling heuristics, a real headless focus journey, blocked local network requests and credential-scrubbed browser process behavior.
- The Playwright requirement allows 1.64.x, including the 1.64.0 version pinned by an optional Hermes component. Eight Linux tests passed with 1.64.1; a fresh warmed-cache Hermes profile enabled the plugin and all eight passed in its managed Playwright 1.64.0 environment. A prior exact 1.64.1 pin caused a Hermes dependency conflict. This is not a fresh online bootstrap or a Windows browser test.
- A self-authored two-button fixture returned two expected matches from the plugin. A separate headless browser run with JavaScript and network requests disabled was visually inspected after each Tab; the visible focus outlines followed the same order. The separate screenshots are not produced or evaluated by the plugin and do not establish accessibility conformance.
- Static checks do not establish accessibility conformance. Dynamic sites, screen readers, production visual focus, broader Windows browser behavior, a reviewed demo and a complete publication audit remain unverified.
- 2026-11-07: real-page trial (a saved 345 KB production government web page, Playwright 1.64 in a private venv, system Google Chrome, disposable profile). `accessibility_inspect_html` scanned 1,356 elements and reported 20 issues beginning with duplicate IDs; an independent count of the page found 14 duplicated ID values, consistent with the report. `accessibility_keyboard_walk` pressed Tab in headless Chrome and reported the first four stops in order (Sitemap, Skip to main content, homepage link by aria-label, then the search field), all matching the expected selectors; the observation that the skip link is the second tab stop is a real property of that page. Not verified: contrast, focus visibility, screen readers, dynamic behaviour, Windows Edge on this run, assistive technology. Temporary folders deleted.
